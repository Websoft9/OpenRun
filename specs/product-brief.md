# OpenRun Product Brief

## Positioning

OpenRun is an **enterprise digitalization intelligence service** for FDEs, OPCs, consultants, and transformation teams. It combines a curated open source software catalog with a process knowledge graph and AI-assisted analysis to help users diagnose business processes, match standard processes, recommend software, and produce implementation advice.

It is not just a software directory. The catalog is the supply side; the process knowledge graph and advisory workflow are the core value.

## Users

- FDEs and forward-deployed engineers
- OPCs and enterprise digitalization consultants
- Transformation, IT, operations, and process improvement teams
- Software evaluators who need process fit, not only feature lists

## Problem

Enterprise digitalization knowledge is fragmented:

- Customers describe pain points in business language, not software categories.
- Consultants must translate those pain points into processes, capabilities, and software options.
- Software directories organize by vendor or technical category, which does not answer "what should this enterprise change?"
- Process frameworks, software capabilities, implementation patterns, and evidence live in separate places.
- AI recommendations are hard to trust without traceable process codes, sources, and confidence.

## Value

- A business-function-first view of the catalog
- A PCF-aligned process model from L1 domains to L2/L3 processes
- Software-to-process fit mappings with evidence and confidence
- AI-assisted diagnosis: from customer problem to process, gap, software shortlist, and implementation advice
- Bilingual, traceable reports for client-facing work
- Reusable implementation patterns, prerequisites, risks, and KPIs

## Knowledge Model

```
PCF-aligned L1 process domain
        -> L2 process group
            -> L3 process
                -> software fit / capability
                    -> implementation pattern
                        -> recommendation and report
```

The process framework is a knowledge backbone, not a UI tag. The software-to-process mapping is the core proprietary asset.

## MVP Scope

- Curated self-hosted open source catalog
- PCF-aligned process domains as the primary enterprise-view classification
- Industry, market, platform, and software-type facets
- PCF-aligned L1/L2/L3 process model and browse/API surface
- Software-to-process mapping schema and evidence fields
- Admin review and publishing
- Public submission flow

## Next Scope

- Licensed full PCF or equivalent process framework
- AI advisor workflow with process matching and gap analysis
- Implementation pattern library
- Client report generation with citations, assumptions, and confidence
- Assessment and recommendation history

## Non-goals

- Claiming an unlicensed APQC PCF dataset as official
- Replacing human consultants or implementation partners
- Automatic deployment or one-click implementation
- Full market coverage in the first release
- Treating use cases as another category tree

## Success Metrics

- Process coverage across L1/L2/L3
- Percentage of published software with reviewed process mappings
- Recommendation acceptance by FDEs/consultants
- Time saved in process diagnosis and software shortlisting
- Every recommendation traceable to process, software, and source evidence
- Bilingual report usability
